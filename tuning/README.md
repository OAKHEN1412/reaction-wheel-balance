# บันทึกการจูนกับฮาร์ดแวร์จริง

ไฟล์ในโฟลเดอร์นี้เก็บ "ผลที่วัดได้จากเครื่องจริง" ทั้งหมด แยกจาก `sim/out/` ซึ่งเป็นผลจำลอง
ตัวเลขในนี้คือที่มาของค่าใน `firmware/reaction_wheel_balance/config.h` ถ้าจะเปลี่ยนค่าใด ควรอ่านเหตุผลตรงนี้ก่อน

| ไฟล์ | เนื้อหา |
|---|---|
| `jump_runs.csv` | ทุกครั้งที่ยิง `jump` พร้อมพารามิเตอร์ ผลลัพธ์ และเหตุผลที่ล้ม/ยกเลิก |
| `balance_gains.md` | การจูนเกน Kd และผลที่วัดได้ |
| `motor_fg.md` | ผลวัดมอเตอร์ (step response) และคุณภาพสัญญาณ FG |
| `logs/*.log.gz` | telemetry ดิบ (CSV: `ms,state,theta_deg,theta_dot_dps,wheel_rpm,cmd_rpm,duty`) |
| `tools/` | สคริปต์วิเคราะห์ log |

## วิธีใช้สคริปต์

```powershell
py -X utf8 tuning\tools\jumpstat.py <log> 0      # สรุป 1 ครั้งของ jump
py -X utf8 tuning\tools\wobble.py <log>          # ความส่ายตอนทรงตัว (SD, คาบ, ความเร็วล้อ)
py -X utf8 tuning\tools\episodes.py <log>        # ไล่ทุกช่วง BALANCING ในไฟล์
```

แตกไฟล์ log ก่อนใช้: `gzip -d -k tuning\logs\<ไฟล์>.log.gz` หรือเปิดด้วยโปรแกรมที่อ่าน .gz ได้

## วิธีเก็บ log ใหม่

1. เปิด telemetry ด้วยคำสั่ง `tel 1` แล้วบันทึกทุกบรรทัดที่ออกมาทาง serial
   (หน้าเว็บ `tools/imu_viewer.html` มีปุ่ม **Record CSV** ให้โหลดเป็นไฟล์ได้เลย)
2. บีบอัดแล้ววางไว้ใน `tuning/logs/`
3. เพิ่มแถวใน `jump_runs.csv` หรือหัวข้อใน `balance_gains.md` พร้อมเหตุผลของการเปลี่ยนค่า

## สรุปสั้น (2026-09-21)

- **ทรงตัว:** ใช้ได้ดี Kd 500 ส่ายแค่ SD 0.27–0.34°
- **ลุกขึ้นเอง:** `jump 550 450 8 75` สำเร็จ **3 ใน 3 ครั้ง** (ก่อนหน้านี้ 3 ใน 10) ตั้งเป็นค่าเริ่มต้นแล้ว
- **กติกาส่งต่อที่ใช้ได้จริง:** ดูที่ **ความเร็วตอนส่งต่อ** ไม่ใช่มุมอย่างเดียว
  เตะจนความเร็วถึง 90 °/s → หยุดเตะปล่อยไหล → ส่งต่อเมื่อมุม ≤ 8° และความเร็วอยู่ในช่วง 60–90 °/s
  (ถ้าไหลแล้วช้ากว่า 60 °/s จะกลับไปเตะต่อ)
- **สูตรพลังงาน `v = √(2K(1−cosθ))` ใช้ไม่ได้** เพราะหลังส่งต่อโหมดทรงตัวก็ออกแรงเพิ่มด้วย ไม่ได้ไหลขึ้นเปล่า ๆ
- **ข้อจำกัดของเครื่อง:** มอเตอร์เร่งได้จริงประมาณ 40 rad/s² ตอนออกแรงต่อเนื่อง น้อยกว่าที่โมเดลคาดประมาณ 3 เท่า
  (น่าจะติดกระแส) ทำให้ไม่มีแรงเหลือมากหลังส่งต่อเข้าโหมดทรงตัว

## สรุปการลุกขึ้นเองบนชุด Nano (2026-09-22)

ยิงไปประมาณ **90 ครั้ง** ในวันเดียว ค่าที่ดีที่สุดได้ **3 ใน 8 (38%)** — ยังไม่น่าพอใจ
log ดิบ: `logs/nano_jump_campaign.log.gz`

### กลไกการล้มเหมือนกันทุกครั้ง

หลังรับช่วง duty ชนเพดาน 21-44% ของเวลา → ล้อชนความเร็วสูงสุด → แรงบิดเหลือศูนย์ → โครงพุ่งเลยไป 15-19°
ส่วนครั้งที่สำเร็จ **duty ตัน 0%** ทุกครั้งโดยไม่มีข้อยกเว้น

**ตัวชี้ขาดคือมีกำลังเหลือหรือไม่ ไม่ใช่ค่าพารามิเตอร์**

### สิ่งที่ลองแล้วไม่ช่วย

| ลอง | ผล |
|---|---|
| ความเร็วส่งต่อ 40 / 50 / 55 / 65 / 75 | 55 ดีสุดแต่ไม่ทิ้งห่าง |
| มุมส่งต่อ 4 / 5 / 8 องศา | 8 ดีสุด มุมเล็กกลับแย่กว่า |
| Kw 1 แทน 3 | แย่ลงชัดเจน (0/5) |
| ลดเวลาเตะเฉพาะฝั่ง + | ไม่ช่วย |

### บทเรียนเรื่องวิธีวัด ⚠️

ระหว่างวันนี้ผมตั้งกฎจากข้อมูลชุดเล็กแล้วมันพังเมื่อเจอข้อมูลใหม่ **3 ครั้ง**:

1. "มุมส่งต่อ 6-7° ดีกว่า 4°" — จาก 6 ตัวอย่าง พอทดสอบจริงที่มุม 4-5° ก็ได้ผลพอกัน
2. "Kw=3 ทำให้พจน์ Kw ใหญ่เกินตอนรับช่วง" — คำนวณแล้วพจน์นั้นเล็กมาก ไม่ใช่สาเหตุ
3. "ต้องมีล้อหมุนค้าง ≥90 rpm ตอนรับช่วง" — แยกข้อมูล 15 ครั้งแรกได้สมบูรณ์แบบ (สำเร็จ 97/107/138 · ล้ม 3-73) พอลองชุดใหม่ได้ **2/8** จึงถอนกฎออก

**ทุกครั้งคือการจับสัญญาณรบกวนมาเป็นกฎ** ตัวแปรที่วัดได้ทุกตัว (มุม ความเร็ว ความเร็วล้อ ฝั่ง) มีช่วงที่ทับซ้อนกันมากระหว่างครั้งที่สำเร็จกับล้ม
**ถ้าจะสรุปกฎใหม่ ต้องมีอย่างน้อย 20-30 ตัวอย่าง และต้องยืนยันกับชุดข้อมูลที่ไม่ได้ใช้ตั้งกฎ**

### สองอย่างที่เก็บไว้ (มีเหตุผลเชิงฟิสิกส์ ไม่ใช่แค่ตัวเลขสวย)

1. **Capture blend** (`CAPTURE_BLEND_MS` 350 ms, `CAPTURE_KP_SCALE` 0.25)
   Kp ที่มุม 8° สั่งความเร่ง ~160 rad/s² แต่มอเตอร์ทำได้ ~40 → สั่งเกินกำลัง 4 เท่า
   จึงหรี่พจน์มุมลงช่วงแรกให้เน้นหยุดการหมุนก่อน แล้วค่อยไล่ระดับขึ้น
2. **COAST เช็คความเร็วก่อนมุม**
   เดิมเช็คมุมก่อน ทำให้ส่งต่อโครงที่ไหลมาจนเกือบหยุด (13-34 °/s) ซึ่งล้มทุกครั้ง ตอนนี้จะกลับไปเตะซ้ำแทน

### ข้อจำกัดที่แท้จริง

ตอนทรงตัวปกติ เอียง 2° ใช้ duty 0.25 → **มุมสูงสุดที่ดึงกลับไหวประมาณ 8° และนั่นคือกรณีล้อหยุดนิ่งไม่มีความเร็ว**
แต่ตอนรับช่วงจริงมีทั้งมุม 6-8° ความเร็ว 40-60 °/s และล้อที่หมุนค้างอยู่ — **รวมแล้วเกินกำลังมอเตอร์**

ระบบจึงทำงานอยู่บนเส้นแบ่งพอดี ความต่างเล็กน้อยที่วัดไม่ได้จึงพลิกผลได้ ซึ่งอธิบายว่าทำไมปรับค่ายังไงก็ไม่ขยับเกิน ~40%

**การปรับพารามิเตอร์ไปไม่ถึง 99% บนฮาร์ดแวร์ชุดนี้** ต้องแก้ที่ตัวเครื่อง:
- **ลดมวลบนโครง โดยเฉพาะส่วนบน** ← น่าจะได้ผลมากที่สุด ชุด Mega เดิม (บอร์ดอยู่นอกโครง) เคยทำได้ 3/3
- เพิ่มความเฉื่อยล้อ (แลกกับปั่นล้อช้าลง ต้องวัดจริง)
- เพิ่มกระแสจากแหล่งจ่าย (ผู้ใช้เปลี่ยนไม่ได้)
