# บันทึกการจูนกับฮาร์ดแวร์จริง

ไฟล์ในโฟลเดอร์นี้เก็บ "ผลที่วัดได้จากเครื่องจริง" ทั้งหมด แยกจาก `sim/out/` ซึ่งเป็นผลจำลอง
ตัวเลขในนี้คือที่มาของค่าใน `firmware/reaction_wheel_balance/config.h` ถ้าจะเปลี่ยนค่าใด ควรอ่านเหตุผลตรงนี้ก่อน

| ไฟล์ | เนื้อหา |
|---|---|
| `jump_runs.csv` | ทุกครั้งที่ยิง `jump` พร้อมพารามิเตอร์ ผลลัพธ์ และเหตุผลที่ล้ม/ยกเลิก |
| `balance_gains.md` | การจูนเกน Kd และผลที่วัดได้ |
| `motor_fg.md` | ผลวัดมอเตอร์ (step response) และคุณภาพสัญญาณ FG |
| `logs/*.log.gz` | telemetry ดิบ (CSV: `ms,state,theta_deg,theta_dot_dps,wheel_rpm,cmd_rpm,duty`) |
| `tools/` | สคริปต์วิเคราะห์ log |

## วิธีใช้สคริปต์

```powershell
py -X utf8 tuning\tools\jumpstat.py <log> 0      # สรุป 1 ครั้งของ jump
py -X utf8 tuning\tools\wobble.py <log>          # ความส่ายตอนทรงตัว (SD, คาบ, ความเร็วล้อ)
py -X utf8 tuning\tools\episodes.py <log>        # ไล่ทุกช่วง BALANCING ในไฟล์
```

แตกไฟล์ log ก่อนใช้: `gzip -d -k tuning\logs\<ไฟล์>.log.gz` หรือเปิดด้วยโปรแกรมที่อ่าน .gz ได้

## วิธีเก็บ log ใหม่

1. เปิด telemetry ด้วยคำสั่ง `tel 1` แล้วบันทึกทุกบรรทัดที่ออกมาทาง serial
   (หน้าเว็บ `tools/imu_viewer.html` มีปุ่ม **Record CSV** ให้โหลดเป็นไฟล์ได้เลย)
2. บีบอัดแล้ววางไว้ใน `tuning/logs/`
3. เพิ่มแถวใน `jump_runs.csv` หรือหัวข้อใน `balance_gains.md` พร้อมเหตุผลของการเปลี่ยนค่า

## สรุปสั้น (2026-09-21)

- **ทรงตัว:** ใช้ได้ดี Kd 500 ส่ายแค่ SD 0.27–0.34°
- **ลุกขึ้นเอง:** `jump 550 450 8 75` สำเร็จ **3 ใน 3 ครั้ง** (ก่อนหน้านี้ 3 ใน 10) ตั้งเป็นค่าเริ่มต้นแล้ว
- **กติกาส่งต่อที่ใช้ได้จริง:** ดูที่ **ความเร็วตอนส่งต่อ** ไม่ใช่มุมอย่างเดียว
  เตะจนความเร็วถึง 90 °/s → หยุดเตะปล่อยไหล → ส่งต่อเมื่อมุม ≤ 8° และความเร็วอยู่ในช่วง 60–90 °/s
  (ถ้าไหลแล้วช้ากว่า 60 °/s จะกลับไปเตะต่อ)
- **สูตรพลังงาน `v = √(2K(1−cosθ))` ใช้ไม่ได้** เพราะหลังส่งต่อโหมดทรงตัวก็ออกแรงเพิ่มด้วย ไม่ได้ไหลขึ้นเปล่า ๆ
- **ข้อจำกัดของเครื่อง:** มอเตอร์เร่งได้จริงประมาณ 40 rad/s² ตอนออกแรงต่อเนื่อง น้อยกว่าที่โมเดลคาดประมาณ 3 เท่า
  (น่าจะติดกระแส) ทำให้ไม่มีแรงเหลือมากหลังส่งต่อเข้าโหมดทรงตัว
